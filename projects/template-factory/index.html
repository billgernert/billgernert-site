Project story

The template factory

Windows builds in this lab start from a golden image, so the image path had to become its own project. The stable version is not "patch the template and hope." It is a rebuild path that promotes a new image only after it has already proved itself.

The old loop failed for predictable reasons

The first design was the obvious one. Boot the template, patch it, run sysprep, shut it down, and repeat next month. It broke in the way stateful Windows image maintenance tends to break. Sysprep rearm limits became a recurring problem, repeated runs made recovery ugly, and a single bad patch cycle could leave the provisioning path waiting on the template it needed.

That was the useful failure. It made the real requirement obvious: patching the next image could not make the current good image unavailable.

The current path is rebuild, verify, then move the tag

The replacement design builds several custom Windows images as code on a weekly schedule and lets them patch forward under automation. The provisioning pipeline does not look up a fixed VM ID. It resolves the current image by tag, which means a known-good template stays in place until the next image exists and has already been checked.

That tag move is the real promotion step. If the new image fails its own build or verify path, the old image is still the one the provisioning story sees. There is no renumbering, no scramble to roll back a broken template in place, and no downtime for the server builds that depend on it.

What this changed

The public provisioning write-up calls this out directly because it was the hardest part of the whole server-build story. Tag-based lookup let the provisioning pipeline treat the template as one stable input even while the image project kept evolving behind it. That is what turned template maintenance from a recurring outage risk into a background factory.

The honest scope is narrower than "all server builds." Windows uses this path. Linux does not need it, because Linux boots a shared cloud image and avoids the golden-template dependency entirely.
