Project story

Self-healing monitoring

The monitoring path in this lab does more than alert. It decides whether the failure is safe to repair directly, whether it needs an operator-held plan, or whether it should stop and escalate with context instead of pretending a guess counts as recovery.

Classify first, then split the work

A broken host does not get one generic "self-heal" action. The engine reads the failure and separates the safe drift from the risky drift. If the issue is something like a moved address or a stale monitoring key, the fix can be applied at the server side directly. If the repair needs a touch on the host itself, the engine writes the full plan and sends it for approval before anything runs.

That split is OS-aware. Linux and Windows do not get the same remediation path, and the roles that run here are the monitoring repair roles only. The provisioning roles are kept out of this path on purpose, because "self-heal" is not permission to rebuild a live machine.

The approval boundary is load-bearing

The full remediation plan is emailed before any host-level change happens, and it waits at an operator gate. If nobody approves it, the plan times out untouched. That makes the automation useful without letting it quietly cross from proposing into doing.

One narrow path is fully automatic today: restarting a single stateless service. It is fenced by a maintenance-window guard, a hard two-attempt cap so it cannot loop forever, and an allowlist on the host that permits exactly one command and nothing else.

The record says only what the engine can prove

The audit trail does not claim a magical green end state. Each run records whether the engine applied a direct fix, dispatched a host plan, or escalated. It does not claim the host is healthy afterwards, because that verification loop is not in place yet and inventing that verdict would make the log worse than useless.

That is the useful limit to name. The platform can explain what it attempted and why. It is honest about the fact that "attempted" and "confirmed healthy afterwards" are still different statements.
