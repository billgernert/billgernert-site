Project story

AIOps morning triage

I built this because the first hour of an incident was being spent opening four consoles and reconstructing the same timeline by hand. The morning job now brings Alertmanager, Zabbix, Jenkins, and Proxmox Backup Server into one finding model, preserves the source evidence, and sends me a short list of what deserves attention.

Four systems become one overnight record

Jenkins starts the chain. One read-only collector asks Alertmanager for firing alerts, one uses the Zabbix API for host and service problems, one walks the Jenkins job tree for failed builds, and one reads Proxmox Backup Server health through the same code that produces the backup digest. Each source is normalized into PostgreSQL with a signature, severity, host when known, source payload, and collection window.

Every collector also writes its own run row before it touches the source. That is important: an empty Alertmanager result can mean a quiet night, while a missing collector run means the evidence was never gathered. A freshness check watches those run rows so a silent collector failure cannot produce a reassuring empty email.

Correlation is code; language models explain the remainder

Deterministic code groups repeated signatures and same-host findings before a model sees anything. PostgreSQL keeps earlier classifications and my later dispositions, so known maintenance noise does not have to be rediscovered every morning. A local Ollama model handles the common classification path. Critical or low-confidence cases can receive a second opinion, but that opinion is still only advisory text.

The second-opinion path no longer uses metered Claude or OpenAI API calls. Prometheus stores an hourly snapshot of subscription consumption. A headless router checks that snapshot, preserves a reserve for interactive work, and selects Codex or Claude only when the measurement is fresh and capacity remains. If neither subscription is safe to use, the local result stands. That removed the incremental token charge and the model API credentials from the scheduled job.

The safety boundary is visible in the data flow

Vault supplies the read-only source and mail credentials at run time. Findings land in PostgreSQL. The model can label a finding actionable, known noise, or needing more information, and it can suggest the first diagnostic check. It cannot call Jenkins, Zabbix, Alertmanager, Proxmox, or a shell. A malformed or unavailable model leaves the original severity intact.

The result is rendered by the production HTML template and sent through the lab SMTP path. The email carries collector health, correlated incidents, rationale, and the next check. Prometheus and Grafana watch the job result and duration separately, so delivery is evidence, not the only health signal.

Where I am taking it next

The next useful improvement is better cross-source correlation: time proximity, deployment context, and a shared incident signature instead of grouping mainly by host. The real-time Alertmanager receiver already uses the same finding and disposition store, so the morning digest and an active incident can converge on one memory instead of becoming separate tools.

Automated remediation remains behind a deliberate gate. Before I let an actionable finding draft even a review-only change, I want a measured run of digest quality, a low false-actionable rate, working disposition overrides, and bounded model usage. The destination is a draft pull request that still requires human review, not an agent with permission to operate the lab.
