Project story

The job reporting pipeline

This is the application pipeline that turns the platform from pure infrastructure into something carrying a real workload: scheduled collection, enrichment, scored reporting, and a database path that treats merged code and applied schema as different facts.

A real application is the honest platform test

The job-search platform matters here because it is not a stateless demo. It has a database, a scheduled data pipeline, and a report that has to be correct enough to be worth reading. That forces the surrounding platform to carry the kinds of state and sequencing a simpler service can hide.

The collect, enrich, and report stages run on a schedule, so the content stays current without a manual refresh step. Secrets come from Vault at run time, and the application is deployed through the same reviewed and reconciled path as the rest of the cluster.

The real gotcha was schema, not UI

The most useful failure from this project was a migration lesson. A merged PR that adds a database migration does not change the live schema. The schema changes only when the pipeline's migrate stage actually runs. Treating "merged" and "applied" as the same state is how a report starts expecting columns the database does not have yet.

That became a standing rule. Trust the database for what is live, not the repository for what should be live. The report path is only as honest as the schema it is reading.

The scoring path is built to explain itself

The score is not useful if it cannot show why it landed there. The reporting side is constrained to describe what it found in the source data rather than to bluff past missing evidence. That makes the report less flattering than an unconstrained summary and much more useful when I need to decide whether the output is worth acting on.

The scoring and resume paths now use the same hourly subscription-usage router as AIOps. Codex or Claude is selected from measured headroom, with a reserve held back for interactive work. This removes per-call model API billing from the scheduled pipeline while keeping the subscriptions themselves in the cost story.

A public version of the dashboard

The private dashboard includes posting titles, companies, links, application history, and resume-specific scoring evidence. This public view keeps the operating contract and strips the records that would turn a portfolio page into a copy of my job search.
