Project story

The job reporting pipeline

I wanted one place to answer three questions: what is new, what is actually a fit, and what needs a response. Six Jenkins jobs collect board and mailbox alerts, normalize them in PostgreSQL, enrich and score the postings, send a daily report, calibrate the scorer, and back up the database.

Collection starts with feeds and a shared mailbox

The collection job polls the supported job-board and ATS feeds, then reads the shared jobs mailbox. Indeed and LinkedIn alerts arrive as email digests, so the collector parses the message, extracts the canonical posting URL, and sends it through the same normalization path as an API result. Greenhouse, Lever, and Ashby postings keep their source metadata instead of being reduced to an email-shaped blob.

PostgreSQL is the system of record. URL and source identifiers handle duplicates, while liveness checks close postings that disappear and repost detection relates a new listing to an older one. Every collection run records its own outcome, which is how the dashboard distinguishes no new jobs from a collector that never completed. The normal daily intake is bounded at 50; a manual backlog run can drain accumulated mail without changing that steady-state limit.

Enrichment is a queue, not one oversized model prompt

The enrichment job takes unprocessed postings in bounded batches. Deterministic parsers pull out salary ranges, location, remote status, deadlines, and skills first. A local Ollama model handles the broad relevance pass. The headless scoring path then compares evidence from the posting with the resume rubric and stores both the score and its explanation, so a 60 means there is reviewable evidence behind it.

Harder scoring and resume work uses the same hourly subscription router as AIOps. Prometheus reports Codex and Claude usage, the router preserves an interactive reserve, and Jenkins launches the provider with available headroom. No scheduled path retains the old Claude API fallback. If usage is stale or both subscriptions are full, the item stays queued instead of silently spending through a metered API.

Six Jenkins jobs keep the responsibilities separate

jobsearch-collect ingests and reconciles postings. jobsearch-enrich parses, classifies, and scores them. jobsearch-digest sends the daily high-fit and expiring-posting report. jobsearch-scorer-eval checks scoring behavior against judged examples. jobsearch-db-backup writes the database recovery artifact. The manual jobsearch-application path changes lifecycle state and produces application-specific material without giving the scheduled collectors permission to apply on my behalf.

The migration stage runs before code that expects a new schema. That rule came from an early failure where merged code and the live database disagreed. The repository describes the intended schema; PostgreSQL reports the applied schema. Jenkins has to make those states converge before an enrichment or digest stage is allowed to trust a new column.

The report is the operator interface

The private Grafana dashboard shows open high-fit postings, source mix, collection age, enrichment backlog, application state, and scoring evidence. The daily email pulls the decisions forward: new high-fit matches, approaching deadlines, and records that need more information. Titles, companies, links, contacts, application history, and resume evidence stay private.

Next I want to close the quality loop between applications and the scorer. The evaluation job can already compare predictions with judged examples; the next step is to make response outcomes a separate calibration signal without letting a small or biased sample rewrite the rubric. Company enrichment and skill-gap reporting will remain opt-in until their signal is better than the extra model work they create.

A public version of the dashboard

The public Grafana view keeps the operational evidence and removes the job-search records. It shows live Jenkins result history, duration, and daily run count for collection, enrichment, digest delivery, and database backup. That is enough to demonstrate the pipeline is operating without publishing where I applied or what the scorer said about a specific employer.
