Application delivery project

Trip planners, from the lab to Cloudflare

I built these apps to plan trips, then used them to work through two ways of hosting a web application. Production runs on Cloudflare. The lab copies are now the worked example for a shared deployment path.

Try the public previewsView the preview code

They started as trip-planning tools

The first apps brought places, maps, and daily choices together for Nashville, the Dominican Republic, London, and Paris. The interfaces use React and TypeScript, with Vite producing the static build. London and Paris share one build that chooses the city from the hostname.

In the lab, Nginx serves the interface from a container. A small API stores the shared itinerary on persistent storage in Kubernetes, so a saved choice can appear in another signed-in browser. Those separate app deployments became the starting point for the platform work.

Moving production to Cloudflare

I adapted the static builds for Cloudflare Pages and moved shared itinerary storage to D1, Cloudflare's managed database. A Worker handles the API requests between the browser and D1. Cloudflare Access uses Microsoft Entra sign-in to protect the private apps.

Development and production have separate hostnames and databases. I test a change in development before promoting it, while the independent Kubernetes copies remain available in the lab. The move changed where the files and saved plans run without turning the private itineraries into public content.

Turning four deployments into a paved road

The apps repeat the same deployment needs: a static interface, saved state, a hostname, and sign-in protection. I am using the lab copies to build one shared deployment definition for that shape of application. That is the paved road, or golden path: a supported way to deploy an app without assembling its hosting and access controls separately each time.

The wider project adds Access configuration through reviewed changes and a portal template that opens a pull request for a new web app. The shared deployment work is still in progress; the Access automation and web-app template are subsequent steps. The public previews below use the portfolio site's existing publishing pipeline.

These are independent public versions adapted from the vacation interfaces. They contain real places and hotel choices, with blank travel dates and no selected hotel. Personal bookings and private itineraries are excluded.

Choose your own dates, add stops, and rearrange each day. Optional suggested itineraries use the listed places. Your plan stays in this browser, with no login or shared database. You can download a backup or print your itinerary.
