Project story

Automated certificate and secret renewal

This is the rotation path that keeps public certificates, internal trust, and the secret material around them from turning into calendar work. The point is not one certificate at a time. The point is keeping expiry from becoming an outage class at all.

Why this pipeline exists

Certificate work becomes fragile the moment it depends on memory. A public hostname expires, an internal service presents the wrong trust chain, or a credential used to fetch the next secret is sitting in a file it should never have touched. The renewal path exists so those cases are a scheduled maintenance story instead of a midnight fire drill.

The site has both halves of the problem. Public hostnames terminate at the edge and need a public certificate path. Internal services use the lab's own certificate authority, because a public CA should never vouch for names that do not exist on the public internet.

What the run actually changes

For public names, cert-manager drives DNS-01 issuance so the certificate renews before it is close enough to matter. For internal services, the trust anchor is Active Directory Certificate Services, and the useful property is that every domain-joined machine is told to trust it once. Rotating an internal certificate then becomes a normal maintenance event instead of a fleet-wide exception list.

The secret side is handled the same way the rest of the lab is handled. Connection details and credentials come from Vault at run time. They are not committed, and they do not sit on disk waiting for the next rotation to inherit them by accident.

Evidence and the limit that still matters

The Vault cluster page shows the internal side of this clearly. Each endpoint presents a certificate issued by AD CS rather than a self-signed fallback, and the expiry path is watched by a check that reads the certificate the service is actually presenting. That closes the easy lie where the source file looked current but the live endpoint was serving something older.

The remaining limit is named here because it matters: not every internal certificate is on a full zero-touch renewal path yet. Some yearly certificates are still issued by hand and watched explicitly for expiry, which is an honest improvement over forgetting them but not the same thing as saying the whole estate is already hands-off.

Live certificate and PKI evidence

This public-safe dashboard reads the certificates that services are presenting now. It shows the certificate horizon, the secrets service state, and lifetime by descriptive service name. Addresses, certificate subjects, management links, and internal source labels stay private.
