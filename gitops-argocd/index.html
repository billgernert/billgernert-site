GitOps with Argo CD

GitOps means the cluster is supposed to look exactly like what is committed in git, and a controller watches for any difference. This lab runs Argo CD that way, with one deliberate choice: automatic sync is turned off. Argo detects drift and reports it, and never changes anything on its own. That was proven live by scaling a workload by hand, watching Argo mark it out of sync, and confirming it touched nothing until a person clicked sync.

What GitOps is here

The workloads in the cluster used to be applied by hand from runbooks: a person ran the apply command for each service directory. That works until the live cluster and the committed files quietly drift apart and nobody can say which is right. GitOps closes that gap. A controller, Argo CD, reads the committed manifests and continuously compares them to what is actually running. The adoption uses the app-of-apps pattern: one small root definition points at a set of applications, and each application tracks one service directory in the repository. Onboarding a service becomes adding it to that set, and the source of truth is the repository, not somebody's memory of the last apply.

Sync deliberately off

Argo can be told to fix drift automatically, and here it deliberately is not. Every application ships with automatic sync turned off, so Argo detects and reports a difference but applies nothing until a human syncs it. The reason is specific to this estate: several of the tracked directories were themselves never applied yet and carry values that are meant to be resolved at apply time. Turning on automatic sync would have pushed all of those to the live cluster as a side effect of merely adopting GitOps, which is a far bigger and less reversible change than the adoption itself. So the safe posture ships first: detection everywhere, action only on a reviewed, deliberate sync.

Drift detection, demonstrated

The point of GitOps is only real if drift is actually caught, so it was demonstrated end to end on a live workload. A deployment that git declares should run one replica was scaled by hand to two. Within a refresh interval Argo reported the application out of sync and, because automatic sync is off, changed nothing: the workload stayed at two replicas. A manual sync then reverted it to the one replica git declares. Reverting a committed change is the same story from the other direction: the application goes out of sync until someone syncs it back.

One detail is worth stealing. The drift has to be on a field git actually owns, like the replica count. A sync reconciles only the fields the committed manifest manages, so it will revert a replica change but will not strip, say, a stray label that git never set. An early version of this demo drifted a label and would have reported a false success; moving it to the replica count made the demo honest.

Why Jenkins is excluded, on purpose

Not everything belongs under Argo. The build server owns a couple of deploys that it applies through its own pipelines, and those are deliberately kept out of the GitOps surface so the two systems never fight over ownership. The boundary is enforced three ways, and all three were checked live. No application points at those build-server-owned paths. The Argo project is fenced to this one repository and to a named set of destinations, so it cannot be pointed at a foreign source. And no application is allowed to prune, so it cannot delete something it does not own even by accident. The separation is by source path, not by namespace, because the two systems share a namespace and only the path boundary actually keeps them apart.

The webhook and single sign-on

A push to the repository nudges Argo to re-check, so the comparison against git is prompt rather than waiting on a slow poll. The Argo web interface sits behind the same single sign-on as the rest of the lab: you authenticate through the identity provider, and access maps to a role by group rather than a local password. So the one place a person can trigger a sync is itself gated by the same identity and the same review discipline as everything else.
